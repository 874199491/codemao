## 1. 系统总览与数据流

```
编程猫 CRM（Chrome CDP 远程调试 9223 端口，必须已登录）
        │  Node 抓取脚本（fetch_*.mjs，在登录页上下文内执行请求，自动带鉴权）
        ▼
data/ 本地缓存（JSON/CSV：完课明细、直播缺席、接龙、家长聊天、反馈发送结果…）
        │  Python 写入脚本（update_*.py / write_*.py / sync_*.py，统一 py -3.10）
        ▼
钉钉云文档表格
  - 学情表（node N7dx2rn0JbZQBadbCZjmZM42JMGjLRb3，sheet st-f09de483-168637）
  - 补课表 / 邀约跟进 / 课后学情反馈 / NCT考级 / 直播未参加记录 / 触达记录
```

关键约定：
- CRM 抓取一律走 Chrome DevTools Protocol（9223 端口），脚本不自己拼鉴权头。
- 所有写钉钉的脚本必须保证"CRM 已登录 + 数据完整"才写入，否则停止（绝不拿旧数据误写）。
- 周次以 `cohort_start=2026-07-23` 为 W1 起点，`week_length_days=7`，每周两课（W1=第1、2课…）。
- `has_exam_training_lessons=true` 时：第 11、21、31、41、51…课视为赛考集训课，不计入完课/补课/反馈/绩效，课号自动顺延。

## 3. server.py 后端架构

### 3.2 执行机制

- `JobStore`：一次只运行一个任务；日志环形缓冲 1500 行；`request_stop` 用 taskkill 杀进程树。
- `run_job`：逐条命令 subprocess 执行（UTF-8 环境），流式追加日志；失败自动把命令+最近 80 行日志追加到 `docs/工作台持续改进记录.md`。
- 周次多选（`selected_week_commands`）：勾选 N 周 → 每周围绕命令展开 `--week N`；多周时只有最新周 `--skip-makeup` 为 False（补课表只同步最新周）。
- 定时任务：`scheduler_loop` 每 20 秒检查 `workbench-schedules.json`，匹配 weekday+time 触发 `create_scheduled_job`；支持 current/custom 周模式。

### 3.3 HTTP API

- GET：`/api/tasks` `/api/schedules` `/api/summary` `/api/trends` `/api/performance?year=&month=` `/api/feedback-knowledge-suggestions` `/api/config` `/api/profile-capture` `/api/jobs` `/api/jobs/{id}`
- POST：`/api/run`（需 confirmed=true）、`/api/jobs/stop`、`/api/config`、`/api/restart`、`/api/open-crm-login`、`/api/schedules`（含 delete/toggle/reorder/run-now）、`/api/profile-capture/{start,stop,generate}`
- 安全：`valid_local_request` 校验 Host 为 127.0.0.1/localhost 且 Origin 匹配；写类 POST 全部要求该校验。

### 3.4 看板指标（build_completion_metrics）

从最新完课缓存 JSON（`{prefix}-completion-query-latest.json`）计算 5 组学员：
- `finished` 已完课（两课均 已完课）
- `first_lesson_unfinished` 第一课未完课（第二课已完成、第一课未完成）
- `arrived_unfinished` 到课未完课（第一课有到课记录、第二课未完成）
- `absent` 未到课（两课均无到课记录）
- `missing_profile` 信息缺失（无姓名或上课时间）

### 3.5 Profile 生成（复制给其他老师）

1. `start_profile_capture`：启动 `listen_crm_network_all_tabs.mjs` 监听目标老师 CRM 的网络包 → `data/{prefix}-crm-capture.jsonl`
2. 目标老师在 CRM 刷新班级看板
3. `generate_profile_from_capture`：`discover_from_capture.py` 解析捕获 → 探测钉钉学情表表头 → 写入 `teacher-workbench-config.json`（班级 ID、钉钉文档、表结构）

## 4. 线程工作流 run_0724_thread_workflow.py（983 行）

统一入口：`py -3.10 scripts/run_0724_thread_workflow.py <operation> --week N [--skip-makeup] [--fetch-only]`

所有操作前置：`persist_context` → `require_logged_in_crm`（9223 无已登录 CRM 页面即停止）。

| operation | 流程 |
|---|---|
| completion | 校验3班配置（ensure_configured_classes_are_coherent）→ 整理班级 CSV → 刷新学员基线（ensure_completion_student_snapshot）→ fetch_group_lesson_completion_from_crm.mjs 抓完课（并发+失败重试+历史缓存兜底校验）→ update_completion_batch.py 写钉钉 → sync_makeup_sheet.py + format_makeup_sheet.py 同步补课表 |
| live | fetch_live_absence_from_crm.mjs（lookback 动态扩展以覆盖历史周）→ update_live_participation_batch.py |
| completion-and-live | completion+live 抓取并行（--fetch-only），再串行写入 |
| solitaire | 刷新学员名单 → fetch_group_solitaire_from_crm.mjs 抓周五/周六企微接龙 → update_weekly_solitaire.py 增量勾选 |
| feedback | 先 sync_feedback_send_status.py 同步历史发送状态 → fetch_course_detail_from_crm.mjs × 2 课 → create_post_class_feedback_sheet.py 生成反馈表 |
| feedback-send | feedback + generate_week1_personalized_feedback.py 生成个性化话术（--finished-only --pending-only）→ send_week1_personalized_feedback.py 创建企微任务 → --execute 后立即同步标记已反馈（不等企微最终确认） |

### 反馈话术生成（generate_week1_personalized_feedback.py）

- 评级规则（build_feedback，配置在 feedback_rules.rating）：
  - 综合正确率 >= excellent_min_combined_rate（默认 80）→ A+，且需周测存在（excellent_requires_week_test）
  - 综合正确率 >= top_min_combined_rate（默认 95）→ S，且需周测满分（top_requires_week_test_full_score）
  - 否则 base（默认 A）
- 话术结构：opening → completion（完课句）→ evidence（答题情况）+ performance（表现句）→ 「这周主要围绕…展开」+ knowledge（知识点句）→ advice（建议句，A 档且 knowledge 已含"建议"时省略）→ note_praise（笔记表扬，按"是否完成笔记=是"）→ homework_correction（订正提醒）→ week_test_correction（周测提醒）→ closing（按学生 ID 字符和取模选变体）→ 评级行（line_template）→ contact 收尾话术（用 dedupe_keywords 检测前面是否已含类似"随时找我"避免重复）
- 知识点句：weekly_knowledge.weeks.{n} 配置优先；无配置时从课程名推断（infer_topics_from_text / knowledge_topics）

### 反馈发送（send_week1_personalized_feedback.py）

- 动态加载 `skills/codemao-makeup-reminder/scripts/create_makeup_reminder.py` 的 CrmClient 作为发送模块
- 前置：从 9223 Chrome 导出 CRM cookie（export_crm_cookies_from_chrome.mjs）→ 学员按 3 班分类（classify_users，按上课时间兜底）→ checked_user_ids（排除已请假 232）→ user_wechat_info（企微映射）
- 每个学员构造 notify_payload，要求恰好 1 个可发送家长（payload["users"] 长度必须为 1），否则标记 unsendable 跳过
- dry-run：只写 result JSON + 企微 chat_id 缓存；--execute：逐学员 send_notify，每成功一个立即 persist_result（中途失败即抛错，已创建任务保留）
- 结果文件：`data/{prefix}-week{week}-feedback-send-result.json`（sync_feedback_send_status.py 据此同步"是否已反馈"）

安全护栏：
- `ensure_configured_classes_are_coherent`：恰好 3 个班、分别匹配 周五/周六午/周六晚、班级 ID 数值聚类（防混入其他班期）。
- 未来周禁止（`context.start > date.today()` 即停止）。
- 完课缓存兜底：`fetch_failed_used_previous` 只允许已结束的历史周，且必须逐班覆盖全部学员才放行。

## 12. 分层与续费画像实现规则（与 SKILL.md 对应的代码事实）

### 学生长期分层（build_long_term_segmentation.py）

评分（renewal_calibrated_score，0-100）：
```
15 × 总完课率 + 25 × 近4个偶数课完课率 + 30 × (1 - 连续未完课偶数课/4 封顶)
+ 15 × 全课程题目正确率 + 15 × 全课程作答率
```
分层（score_and_layer，含原因标签和策略建议）：
| 分 | 层名 | 触发原因标签（reasons） |
|---|---|---|
| ≥88 | S-高续费稳定 | 无则"长期表现稳定" |
| ≥75 | A-稳定维护 | 无则"整体表现较稳" |
| ≥62 | B-轻度提醒 | 无则"存在轻微波动" |
| ≥50 | C-重点跟进 | 无则"近期表现不稳" |
| <50 | D-高风险挽回 | 无则"综合表现偏弱" |

原因判定阈值：总完课率<0.75、近4周<0.75、连续未完课≥2、题目正确率<0.7、作答率<0.65、最近课未完课、完课耗时标签为"超过7天/未完课"（finish_time_tag：24小时内/3天内/7天内/超过7天）。

### 家长画像与续费判断（build_renewal_profiles.py）

- 家长画像由关键词分类驱动：KEYWORDS 字典 → 决策角色/沟通态度/核心顾虑/续费阻力/续费机会，每个字段附证据片段（evidence_for 取聊天中命中的原文）。
- 续费判断（renewal_decision）：
  - 机会：家长机会权重 ≥3 高机会、≥1 中机会、否则低机会
  - 学生风险：D 层或 score<40 → 高学生风险；C 层或 score<55 → 中学生风险
  - 风险合成：高学生风险+家长阻力≥2 → 高风险"学习表现弱+家长阻力明显"；仅高学生风险 → 高风险"先修复学习信心"；家长阻力≥2 → 中高风险；中学生风险或阻力=1 → 中风险；高机会 → 低风险
  - 动作（next_action）：高风险 → 24小时内私聊；中高风险 → 本周私聊一次；高机会 → 推进续费确认；否则 → 继续每周反馈
  - 高风险挽回方法（high_risk_method）：共情阻力→2周补课计划→用具体数据→两套续学方案→约定确认节点
