# 教师工作台踩坑记录

本文档只记录教师工作台中已经遇到、已经定位或具有明确处理办法的问题。原始执行日志仍由《工作台持续改进记录》保存；这里不堆完整报错，只沉淀可复用结论。

最后更新：2026-08-10

## 使用原则

- 先确认数据源、目标周次、班级和表头，再执行写入。
- CRM 数据可在本地抓取和整理；所有钉钉读取、写入、排序、格式化与回读校验统一走钉钉 MCP。
- 外部写入必须串行执行，写完立即回读；不能只根据命令退出码判断成功。
- 学员匹配优先使用学生 ID，姓名只用于人工核对，不能作为唯一主键。
- 老师手工填写的请假原因、补课时间、备注和手工勾选结果默认保留。
- 工作台副本升级时必须保留老师自己的配置、Cookie、定时任务和运行缓存。

## 快速排查顺序

工作台任务失败时，按以下顺序检查：

1. 看运行记录中的“第几步失败”和第一条业务错误，不要只看最后一段 `CalledProcessError`。
2. 确认 Chrome 调试端口已连接，并且 CRM 页面处于登录状态。
3. 确认本次选择的周次、课程编号和配置班级是否正确。
4. 确认钉钉目标文档、工作表和表头仍然存在。
5. 检查本地缓存是否为空、过期或属于另一位老师。
6. 写入后回读目标单元格，核对值、复选框状态和学员 ID。

## 已确认问题与处理办法

### 1. Chrome 已打开，但 CRM 仍提示未登录

现象：工作台显示需要登录，或 CRM 请求返回 `401`、`not_login`。

常见原因：

- 打开的不是带远程调试端口的 Chrome。
- 登录发生在另一个 Chrome 用户目录或另一个端口。
- Cookie 文件是旧登录态，不能代表当前浏览器会话。

处理：

1. 从工作台拉起指定调试端口的 Chrome。
2. 在该窗口中打开 CRM 并完成登录。
3. 重新运行登录检查，再执行数据任务。

预防：不要把“Chrome 进程存在”当成“CRM 已登录”。

### 2. CRM 返回班级数量不完整或出现 500

现象：提示“配置的班级最新周完课数据未完整返回”，或某个班级 `fetch_failed_used_previous`。

常见原因：

- CRM 单个班级接口暂时返回 500。
- 配置中混入非教学班、失效班级或重复班级。
- 旧缓存包含其他老师或其他周次的数据。

处理：

1. 先核对配置中的 `class_id`、班级名称和实际 CRM 页面。
2. 单独重试失败班级，不能用数量相同的旧缓存冒充本次结果。
3. 班级数据未完整返回时停止钉钉写入。

预防：每次生成配置后保存班级 ID 与班级名称的对应关系，并在写入前校验。

### 3. 学员总数对不上

现象：学情表、CRM 名单和看板总人数不一致。

常见原因：

- 学生调整了上课时间，仍留在旧班级统计中。
- 退费中或已退费学员没有剔除。
- 把多周数据行相加，误当成当前学员总数。
- 使用了上一位老师留下的本地名单缓存。

处理：

1. 以当前登录老师的 CRM 班级名单重新生成学员数据。
2. 按学生 ID 去重，并剔除退费中、已退费名单。
3. 按“周五晚 → 周六午 → 周六晚”排序整行数据。
4. 排序后同时校验 ID、姓名和上课时间，防止列错位。

预防：人数统计必须基于当前有效学员 ID 集合，不能基于周记录行数。

### 4. 排序后表格内容错位或接口不存在

现象：排序失败、提示接口不存在，或上课时间排序正确但其他列与学生错位。

原因：只移动了上课时间列，或调用了不存在/已废弃的排序接口。

处理：

- 使用钉钉 MCP 当前可用的服务端区域排序能力。
- 排序范围必须覆盖除表头外的整张数据区域，而不是只排序一列。
- 回读若干行，同时核对 ID、姓名、时间和周数据。

### 5. 复选框被写成 TRUE/FALSE 文本

现象：单元格显示 `TRUE`、`FALSE`，但不是可点击复选框。

原因：只写入了布尔值或字符串，没有保留/设置复选框数据验证。

处理：通过钉钉 MCP 写入复选框的 `dataValidation.type=checkbox` 和 `checked` 状态，并回读数据验证结果。

预防：涉及接龙、是否反馈、请假等字段时，不能只校验显示文本。

### 6. 接龙更新覆盖老师手工勾选

现象：老师手动勾选过的学生，在下一次更新后变回未勾选。

原因：脚本按照本次 CRM 抓取结果重算整列。

处理：接龙采用增量规则：`新值 = 原来已勾选 或 本次抓到接龙`，只增不减。

预防：取消勾选必须作为单独的明确操作，不能由普通更新隐式完成。

### 7. 学生用孩子昵称接龙，家长微信昵称匹配不到

现象：群内已经接龙，但系统仍判定未接龙。

原因：仅按家长微信昵称匹配，孩子昵称或接龙文本中的学生姓名未纳入。

处理：优先使用学生 ID；无 ID 时使用已确认的家长昵称、孩子昵称和学生姓名映射。模糊匹配结果必须单独标记，不能直接写入。

### 8. 新周无法更新或表头缺失

现象：只能选择旧周，或者更新新周时找不到 `Wn接龙/直播参与情况/到课完课情况`。

原因：周次计算、前端可选周次和钉钉列创建逻辑没有同步。

处理：

1. 按班期开班日期计算周次；当前规则为周四开始、周一结束。
2. 更新前探测表头，缺少当周列时再创建。
3. 创建后重新读取表头，禁止继续使用旧列号缓存。

预防：代码按表头名称定位列，不把固定列字母写死。

### 9. 钉钉新增列后脚本失败

现象：老师在学情表中插入新列后，更新写错位置或找不到字段。

原因：脚本按固定列序号读取和写入。

处理：首次配置和每次运行前探测实际表头；通过标准字段别名映射到真实列。无法唯一识别时停止写入并提示。

预防：列新增通常应兼容，列重名、删除核心列或改成无法识别的名称才应中止。

### 10. 钉钉合并单元格阻止批量写入

现象：返回 `MERGED_CELLS_CONFLICT`，或整块写入失败。

原因：目标范围中包含合并单元格。

处理：先通过钉钉 MCP 读取合并范围；确需写入时取消相关合并，完成写入后按原结构恢复。

预防：不要在未读取工作表结构的情况下直接覆盖大范围。

### 11. 钉钉 MCP 返回 PREPARE_CALL_TOOL_ERROR

现象：格式化补课表时出现“工具调用准备失败，请稍后重试”，导致整个完课流程失败。

原因：钉钉 MCP 的格式化工具临时不可用，业务数据写入与装饰性格式化被绑定成同一个硬失败流程。

处理：

- 核心数据写入成功后，装饰性格式化失败应记录并跳过剩余格式化。
- 不回滚已经正确写入的完课数据。
- 稍后单独重试格式化，并通过 MCP 回读确认。

预防：核心数据和视觉格式分成两个可独立失败的步骤。

### 12. 钉钉写入成功，但中文变成 `???`

现象：接口返回成功，目标单元格却显示 `???`。

原因：Windows PowerShell、Python、CMD 和 JSON 参数之间发生中文编码转换；如果校验程序也使用同一错误编码，还可能产生“假校验通过”。

处理：

1. JSON 命令行参数使用 ASCII 安全的 Unicode 转义，例如 `ensure_ascii=True`。
2. 写入后重新通过钉钉 MCP 读取真实单元格值。
3. 校验常量也使用 Unicode 转义，避免比较两份同样损坏的字符串。

预防：中文外部写入不能只看 `success=true`，必须回读实际值。

### 13. 看板接口返回 HTML，前端却按 JSON 解析

现象：页面提示 `Unexpected token '<', '<!DOCTYPE ...' is not valid JSON`。

原因：接口路径不存在、服务未重启或旧代码仍在运行，服务器返回了 HTML 页面。

处理：

1. 检查请求 URL、HTTP 状态码和 `Content-Type`。
2. 确认接口已经注册到当前运行的服务中。
3. 重启工作台加载最新代码，再刷新页面。
4. 前端解析前先判断响应类型，并展示可读错误。

### 14. 更新代码后页面仍是旧版本

现象：一键更新显示完成，但按钮、接口或页面样式没有变化。

原因：工作台服务仍运行旧进程，仅刷新浏览器不能加载后端新代码。

处理：使用“重启工作台并加载最新代码”，等待新服务启动后再打开页面。

预防：把“刷新数据”和“重启工作台”设计成两个名称明确的操作。

### 15. 副本缺少脚本或模块

现象：出现 `ModuleNotFoundError` 或 `can't open file`，例如缺少 `update_live_participation.py`、`format_makeup_sheet.py`、skill 目录。

原因：打包清单与实际运行依赖不一致，或者更新程序只替换了部分目录。

处理：

1. 从运行入口递归检查导入和子进程脚本依赖。
2. 打包前在全新目录解压并执行烟雾测试。
3. 缺少必要文件时更新程序必须停止，不能继续运行旧文件拼接的新版本。

预防：压缩包不包含老师个人配置，但必须包含运行必需的公共代码与资源。

### 16. PowerShell 或 VBS 启动脚本乱码、语法错误

现象：PowerShell 提示字符串缺少结束符，VBS 提示“无效字符”。

原因：脚本文件编码与 Windows Script Host/PowerShell 读取方式不一致，中文字符被破坏。

处理：

- 启动器和安装脚本尽量使用 ASCII 文案或明确兼容的编码。
- 发布前从压缩包中重新解压，在不同路径下双击验证。
- 路径含空格和括号时必须完整加引号。

### 17. 更新程序覆盖其他老师配置

现象：更新后学员变成另一位老师的，班级、钉钉表或班期恢复成打包者配置。

原因：配置文件、Cookie 或运行缓存被提交到更新包并覆盖本地文件。

处理：更新时保留以下本地文件：

- `data/teacher-workbench-config.json`
- CRM Cookie/登录态文件
- 定时任务配置
- 老师本地运行缓存和映射缓存

预防：仓库和发布包使用无个人数据的示例配置；真实配置只存在老师本机。

### 18. 发送反馈前同步旧记录返回 401

现象：发送本周反馈时，流程先同步上一周发送状态，CRM 返回 `401`，导致本周任务也停止。

原因：旧 Cookie 无效，或者非核心的历史同步被设置为强制前置步骤。

处理：先从当前 CRM 调试浏览器获取有效会话；缺少历史任务或历史同步暂时失败时，按规则跳过并记录，不阻塞本周反馈生成。

### 19. 缺少企微家长映射导致整批反馈停止

现象：一个学生缺少可发送企微映射，整批任务无法创建。

处理：缺少映射的学生单独跳过并记录姓名、ID和原因，其余学员继续创建任务。

预防：发送前生成映射缓存，并在预检页面展示“可发送/缺映射”数量。

### 20. 取消群发返回 422

现象：提示“部分用户已在企微客户端确认发送，发送状态已变更”。

含义：这些消息已经确认发送或状态发生变化，CRM 不允许再次取消。

处理：

- 只取消当前工作台创建且仍处于可取消状态的任务。
- 已确认或已发送的任务记录为不可取消，不重复重试。
- 不能使用“取消全部”误伤其他业务群发。

### 21. 反馈已发送，但学情表没有立即勾选

原因：发送结果登记被推迟到下一次反馈流程，或发送成功记录与当周反馈表匹配失败。

处理：发送成功后立即按学生 ID 和周次更新“是否反馈”，并回读复选框状态；不再等待下一次任务。

预防：发送结果文件必须带周次、学生 ID、任务 ID和发送状态。

### 22. 定时任务页面一直加载或显示加载失败

常见原因：

- `/api/schedules` 没有注册或返回 HTML。
- 工作台仍在运行旧后端。
- 操作列表接口失败，导致下拉框为空。

处理：先检查接口响应，再重启工作台；前端应提供空状态和明确错误，不能无限显示“正在加载”。

### 23. 更新完课数据在启动后立即失败

现象：任务刚开始就结束，外层只显示 `fetch_group_lesson_completion_from_crm.mjs returned non-zero exit status 1`。

已确认原因：完课课次抓取依赖配置中的学生基础快照；文件缺失、为空、结构不正确，或仍属于另一位老师的班级时，旧流程会在读取文件阶段直接退出。

处理：

1. 运行完课抓取前检查班级 CSV 和学生基础快照。
2. 学生快照缺失、为空或未覆盖当前配置班级时，先从当前登录 CRM 自动刷新。
3. 自动刷新后再次校验班级覆盖范围，通过后才继续抓逐课完课数据。
4. 班级 CSV 本身缺失时停止任务，并明确提示重新生成老师配置。

预防：不能因为文件名符合当前班期，就认定缓存属于当前老师；必须校验文件中的实际班级 ID。

## 数据写入安全清单

每次向钉钉表格写入前确认：

- [ ] 文档 node ID、工作表 ID 和工作表名称已经实时查询确认。
- [ ] 已读取目标表头，没有使用旧列号缓存。
- [ ] 学生使用 ID 匹配，姓名核对一致。
- [ ] 已选择正确周次，且只操作当周字段。
- [ ] 退费中和已退费学员已按业务规则处理。
- [ ] 手工备注、请假原因、补课时间和已有勾选不会被覆盖。
- [ ] 写入批次大小符合工具限制。
- [ ] 中文参数经过安全编码处理。
- [ ] 写入后通过钉钉 MCP 回读实际值或复选框状态。

## 2026-08-10 课后作业订正提醒误触发

影响功能：

课后学情反馈、发送已完课学员课后反馈。

现象：

部分周测 100% 正确的学生，反馈话术中仍出现“课后作业有错题，提醒订正”。

触发条件：

学生周测满分，但课中习题不是满分；同时配置中开启了“课后作业有错题提醒订正”。

根因：

生成反馈时把“课中习题正确数/总数”传给了 `homework_correction_sentence`，导致系统把课中习题非满分误判为课后作业有错题。

处理办法：

将订正提醒改为只读取明确的课后作业字段，例如“课后作业错题数”“课后作业正确率”“课后作业正确数/总数”等；没有这些字段时不触发订正提醒。

验证结果：

周测 100%、课中习题非满分、没有课后作业错题字段时，返回空订正提醒；明确传入“课后作业错题数=1”或“课后作业正确率=99%”时，返回配置中的订正提醒。

预防规则：

不要复用课中习题字段判断课后作业错题；新增反馈规则时必须确认字段来源和业务含义一一对应。
