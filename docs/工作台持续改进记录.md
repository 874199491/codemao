### 这轮暴露/复盘的错误

1. 大补丁容易失败
   - 一次性修改多个文件时，补丁上下文稍微不一致就会整体失败。
   - 后续做法：拆成后端、HTML、JS、CSS、文档多个小补丁，逐步校验。

2. PowerShell 输出中文可能看起来像乱码
   - `Get-Content` / `Select-String` 在某些终端编码下会把中文显示坏。
   - 不能只凭终端显示判断文件损坏。
   - 后续做法：用 Python 按 UTF-8 读文件并 `repr` 检查真实内容。

3. 控制台原始日志可读性不足
   - 之前所有日志都是同色纯文本，用户很难快速看到是哪一步失败。
   - 后续做法：日志必须分色、可复制、显示步骤和耗时。

4. 定时任务/自动化必须明确边界
   - 看板关闭后不会后台执行。
   - 这个限制必须在 UI 和文档里反复说明，避免老师误以为电脑关了也会执行。

5. 复用工具函数前要确认参数语义
   - 本轮曾在已撤销的洞察功能里，误把 `data_path(name, config)` 当成了 `data_path(config, path)` 使用。
   - 结果直接调用洞察生成时报错：`AttributeError: 'str' object has no attribute 'get'`。
   - 后续做法：涉及配置解析的工具函数必须先看定义，再写调用；新增接口后至少直接调用一次核心函数。

6. 配置体检要分层，不要一上来做重操作
   - 最容易失败的是钉钉权限、CRM 登录、表头不一致。
   - 但体检页如果一打开就访问外部接口，会让页面变慢，也可能打扰老师。
   - 当前做法：第一层只做本地配置和缓存检查；第二层以后再做“深度体检”按钮，明确告诉用户会访问钉钉/CRM。

7. 中文测试数据在 PowerShell inline script 中可能被转码
   - 本轮用假数据测试表头时，直接写中文字符串被 PowerShell/终端编码转成问号。
   - 后续做法：涉及中文表头的内联测试，使用 `\uXXXX` Unicode 转义，或者直接读取真实文件中的表头。

### 从 CRM 数据还能继续做的功能想法

1. 学员风险雷达
   - 综合以下信号打标签：
     - 连续未到课
     - 到课但未完课
     - 周测未做
     - 课中习题低于阈值
     - 家长消息长期未回复
     - 已请假但未安排补课
   - 输出「高优先级跟进名单」，支持一键复制 ID。

2. 自动生成邀约优先级
   - 接龙未接 + 未请假 + 最近未读/未回复家长消息 = 优先跟进。
   - 已接龙但直播无记录 = 课前提醒或课后核实。
   - 请假学员自动进入补课提醒。

3. 班级健康看板
   - 按班级时间段展示：
     - 学员数
     - 到课率
     - 完课率
     - 接龙率
     - 反馈发送率
   - 能快速看出周五晚、周六午、周六晚哪个班节最需要运营动作。

4. 反馈发送前预检
   - 在创建企微群发前先显示：
     - 待发送人数
     - 缺企微映射人数
     - 已反馈会跳过人数
     - 周测未完成提醒人数
   - 让老师确认“这次到底会发给谁”。

5. 配置体检
   - 检查：
     - 钉钉 node_id 是否可访问
     - learning_sheet_id 是否存在
     - 学情表关键表头是否匹配
     - CRM class_id 是否能拉到数据
     - data_prefix 是否仍为 demo
   - 用红黄绿状态显示，不要等任务执行后才报错。

6. 慢步骤分析
   - 利用当前新增的步骤耗时，后续可自动统计：
     - 哪个脚本最慢
     - CRM 拉取慢还是钉钉写入慢
     - 是否适合并行或批量写入

7. 家长沟通节奏助手
   - 从 CRM 消息记录中识别：
     - 多久没联系
     - 家长最近是否提过请假/问题/时间冲突
     - 是否已经发送反馈但未确认
   - 生成“今天建议先处理的 10 个家长”。
