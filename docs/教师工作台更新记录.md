# 教师工作台更新记录

钉钉持续更新文档：[教师工作台更新记录](https://alidocs.dingtalk.com/i/nodes/ZgpG2NdyVXrAYQbpIPpprraZ8MwvDqPk)

## 2026-08-09

### 看板与运行环境

- 新增“刷新看板”按钮，可重启当前工作台服务并加载磁盘上的最新代码。
- 重启前检测正在执行的任务。
- 任务列表加载增加短暂重试和并发复用。
- 看板支持按周选择更新，并增加每周趋势页面和图表展示。
- 定时任务独立页面支持新建、编辑、启停、删除、立即执行和拖动排序。

### 学情与数据更新

- 完课、直播、接龙、邀约跟进、课后反馈均按周区分。
- 接龙更新改为增量勾选，使用复选框格式并在写入后回读校验。
- 学生时间段更新会剔除退费学员，并按“周五晚、周六午、周六晚”排序。
- 课后反馈支持周测、课中习题、笔记、错题订正、评分阈值、知识点和结尾话术配置。
- 旧周反馈配置默认收起，当前最新周默认展开。

### 配置与复用

- 支持从其他老师的 CRM 登录和钉钉学情表生成配置。
- 支持表头探测、GitHub 更新和本地配置保留。
- 副本不携带个人学生数据、Cookie 和运行缓存。

### 交互与界面

- 学员明细支持按姓名、学生 ID 和上课时间筛选。
- 复制学生 ID 时只复制当前筛选结果。
- 配置弹窗、定时任务页面、周反馈配置和学员明细完成布局调整。

以后每完成一项功能或规则调整，在本页和钉钉文档末尾追加日期、改动内容、影响页面和验证结果。

## 2026-08-10

### 课后反馈与发送状态

- 修复“课后作业订正提醒”误用课中习题正确率的问题。
- 订正提醒不再根据“课中习题正确数/总数”触发，避免周测 100% 正确但课中习题非满分的学员被误提醒课后作业订正。
- 新规则只在反馈数据中明确存在“课后作业错题数/错误数/需订正数/订正数”、或“课后作业正确数/总数”、或“课后作业正确率低于 100%”时触发订正提醒。
- 修复反馈发送后“是否已反馈”不勾选的问题：CRM 发送记录优先使用 `successReceiveUserIdList`，若该字段未返回成功但 `successUserIdList` 已包含对应学生，且消息内容哈希匹配本次反馈，则视为已成功进入企微发送链路并登记已反馈。
- 已同步个人看板和教师工作台副本模板。
- 验证结果：W3 反馈发送记录可匹配 189/189，并成功回写钉钉「课后学情反馈」对应周的“是否已反馈”。

## 2026-08-14

### 接龙更新容错

- 修复接龙更新中“某个时段未抓到接龙群会阻断全部写入”的问题。
- 新规则：只要周五或周六任一时段抓到接龙群，就先写入已抓到的数据；抓不到的时段会跳过并提示稍后单独重跑。
- 如果某个时段抓到的接龙群数量少于配置班级数，会给出警告，但仍写入已抓到的数据，避免有效数据被浪费。
- 接龙时段改为根据配置中的班级标签判断：没有周六班时不再强制要求周六接龙。
- 验证结果：个人看板与教师工作台副本脚本均通过 `py_compile` 语法检查；副本当前解析接龙班期为 `0807`，个人看板解析为 `0724`。

### 更新脚本

- 一键更新脚本改为保留老师本地的 `skills` 文件夹。
- Git 更新前会临时备份 `skills`，更新后恢复，避免老师手动放入的技能目录被仓库更新影响。
- Zip 包更新不再清空覆盖已有 `skills`；只有本地不存在 `skills` 且包内存在时才会初始化复制。
- 验证结果：`update-workbench.ps1` 通过 PowerShell 语法检查。

### 接龙匹配

- 更新接龙前会先自动刷新 CRM 学员名单缓存，再用最新名单匹配接龙昵称，减少因旧名单缓存导致的 0 匹配。
- 当接龙抓取成功但没有任何学生 ID 匹配时，报错信息改为提示检查 CRM 学员名单缓存/老师配置，并只展示部分待核对昵称示例。
- 验证结果：个人看板与教师工作台副本的接龙脚本均通过 `py_compile` 语法检查。
- 接龙搜索不再允许使用 `demo` 作为班期标识；如果老师配置仍是 demo 或为空，会直接提示重新生成配置，避免误搜不到群或写入 demo 缓存。
- CRM 学员名单刷新脚本也会校验 `profile.data_prefix`，未生成有效老师配置时不会再写入 `demo-student-completion-detail.json`。

### 配置生成

- 放宽钉钉文档 nodeId 解析：支持 `/i/nodes/<nodeId>`、带参数的钉钉链接、query 中的 `nodeId`，也支持直接粘贴 nodeId。
- 修复老师生成配置时因钉钉链接未识别而提示 `Provide --node-id or a --dingtalk-url containing /nodes/<nodeId>` 的问题。
- 配置生成时会过滤 CRM 捕获中混入的旧班级：在主 package 的基础上继续按 termId/classId 主簇保留班级，避免类似 `130047-130050` 中混入 `119140/C01091`。
- 更新完课前会校验配置班级是否连贯；发现异常班级会停止并提示重新生成配置，避免混班级写入钉钉。

### 运行记录

- 运行记录区域新增“暂停执行”按钮，可停止当前正在运行的后台任务及其子进程。
- 暂停后任务状态显示为“已暂停”，后续步骤不会继续执行；已经写入外部系统的数据不会自动回滚。
